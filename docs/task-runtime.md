# 任务运行时与模块边界

界面保持独立，任务能力共用。入口负责当前账号、企微身份和任务归属授权；授权之后，共用服务负责操作条件、队列和执行结果。

## 操作入口

- `server/src/services/taskOperations.ts`：完成合并、放弃合并、Merge Request 和发版合并的共用入口。Web、工作台对话和小迪均通过这里排队。
- `jobMergeService.ts`：实际 Git 集成、冲突处理、合并记录和 TAPD 同步。入口层不再各自复制合并队列。
- 分析和代码执行继续复用现有会话 actor、`jobActions` 和 `jobProcessor`，保留两种交互流程，避免在本批进行破坏性迁移。

## 状态

`shared/src/taskState.ts`（`@ai-runtime/shared/task-state`）是前后端共用的纯状态投影，不得导入 Node、数据库、网络或界面代码。它兼容历史任务字段，统一计算分析/实现阶段、待补充、Review、可完成条件和同步提示。HTTP 详情和列表均返回 `taskState`；旧字段仍保留，不需要迁移历史数据。服务端原来的 `domain/taskState.ts` 仅保留兼容转发。

TAPD 状态是外部事实，代码执行阶段是本地状态。预分析不表示已经开始修改；TAPD 同步失败也不撤销已经完成的 Git 合并。手动刷新 TAPD 时，外部已完成状态优先。

## 更新与查询

- `GET /api/jobs/workbench/jobs`：账号范围内的轻量摘要，不包含聊天、附件和文档正文。
- `GET /api/jobs/workbench/conversations/:id?projectId=...`：仅读取当前项目、当前账号的指定会话。
- `GET /api/jobs/workbench/changes`：初始摘要快照及后续 upsert/remove，重连时重新取得快照。
- `GET /api/jobs/:id/stream?continuous=true`：活动事件与 state 快照，包括没有模型事件的 actor 收尾、暂停和引擎切换。
- `GET /api/jobs/changes`：旧 Web 当前身份可见的非工作台任务变更，按需读取单项详情。

`jobChanges.ts` 合并同一轮同步写入，事务结束后通知订阅者。页面不再定时读取完整列表和整份事件历史；SSE 心跳只维持连接，TAPD 仍由用户手动刷新。页面卸载时必须释放订阅，重连时用快照恢复。

## 第二批：模块边界与按需加载

- 页面入口分别加载旧 Web、工作台、工时、统计和接口文档，登录/改密表单独立在 `AuthForms.tsx`，工作台不会因认证而加载工时管理页面。
- `DeferredDialogs.tsx` 在第一次打开时加载代码差异和接口搜索；关闭后保留组件状态。`TapdBugDialog.tsx` 独立负责缺陷草稿、截图、项目/迭代和提交，打开时绑定来源任务，关闭时释放截图地址并忽略过期响应。
- `routes/jobArtifacts.ts` 承载差异、附件和小程序预览/上传路由，继续经 `getAuthorizedJob` 校验原有任务归属；URL、返回格式和队列规则保持兼容。
- `services/git/commitDiff.ts` 负责只读差异解析，`GitService.getCommitDiff` 保留原接口和仓库路径校验。合并、发版和 worktree 写入逻辑继续使用原有实现。

验证按生产构建的实际浏览器资源请求统计，并检查弹窗首次加载、关闭后状态保留、缺陷编辑提交和任务归属；不能用调高 chunk 警告阈值代替减小加载量。

2026-10-15 在本地模拟接口、全新 Edge 浏览器上下文下对比生产构建：工作台首次请求的 JS 文件 gzip 合计由 446,038 字节降至 374,742 字节，减少约 16%；旧 Web 由 376,912 字节降至 367,787 字节。这里统计文件压缩体积，不代表所有网络环境下的耗时；首次打开弹窗时会另行下载对应模块。

## 第三批：工作台执行流程

`workbenchSession.ts` 保留原有导出，是 Web 和小迪共用的入口，并且只创建一个会话调度器。调用方不应自行实例化第二个生产调度器。

- `workbench/controller.ts`：接收消息、校验可接收条件、追加附件、暂停与请求续接。先保存用户输入，再交给调度器处理；合并期间仍拒绝新消息。
- `workbench/worker.ts`：每个任务只有一个运行中的 Promise。分析中有新补充时跳过旧方案；暂停后快速续接必须等旧轮次收尾，随后继续消费已保存输入。
- `workbench/transitions.ts`：集中计算分析开始、修改前准备、待补充、回复、用例生成收尾、中断和暂停的状态补丁；不访问数据库、Git 或 TAPD。
- `workbench/protocol.ts`：模型决策校验、控制消息识别和上下文拼装；沿用现有格式、限制和中文提示。
- `workbench/runtime.ts`：接入模型、Git 工作区、代码执行、测试用例和 TAPD。取消/复位所需的 Git 检查及 TAPD 回写继续在此处理，提交与合并仍经过公共任务操作服务。

这一批不迁移任务数据，不更改 HTTP/SSE 协议、命令、模型提示词和旧 Web 的确认方案流程。实际进入代码修改后才由 `jobProcessor` 标记执行开始并同步 TAPD 进行中；预分析保持原有语义。

验证包括既有流程回归，以及消息入口的暂停后立即续接、分析中取消、执行串行、分析限制和附件绑定。另以重构前实现对照 312 组状态/动作组合，比较状态写入、事件顺序、调用次数与最终结果，仅忽略自动生成的 ID 和时间。

## 第四批：工作台页面数据管理

`WorkbenchPage.tsx` 保留页面布局、筛选、任务打开和对话启动，数据管理拆到 `web/src/workbench`：

- `useWorkbenchSources.ts`：读取代码项目、TAPD 项目和迭代，恢复 URL/账号偏好，加载当前处理人的任务与 Bug。保持显式刷新，清理过期请求的响应处理。
- `useWorkbenchJobs.ts`：管理账号范围内的任务订阅及加载/错误状态；刷新和卸载时释放连接。
- `useWorkbenchHistory.ts`：管理账号浏览器存储、历史删除确认和服务端清理；成功后通知页面更新当前会话和任务摘要。
- `items.ts`、`model.ts`：集中历史与远端条目的合并、任务关联及处理人匹配规则。

账号存储键、URL 参数、接口和交互保持兼容，不迁移浏览器历史。原页面与重构页面分别通过相同浏览器场景，8 个记录检查点一致，覆盖迭代恢复、依赖设置、手动刷新、过期响应、部分失败、历史删除及账号切换。另验证类型筛选和布局切换、代码项目选择及订阅释放。

数据规则测试：在仓库根目录运行 `node --import tsx --test web/src/workbench/items.test.ts`。

## 第五批：独立共享包

`shared` 是本地 npm workspace 包，前端、服务端和小迪统一通过 `@ai-runtime/shared/task-state` 引用任务状态规则；前端不再跨目录引用服务端源码。共享包无运行依赖，使用独立 TypeScript 配置编译，环境类型不包含 Node 或 DOM。

- Web 和服务端的 `prebuild` 自动构建共享包，单独构建任一端也无需手动安排顺序。
- 浏览器构建使用共享源码；服务端开发命令通过 `development` 条件及 tsx 读取同一源码。普通 Node 生产运行读取 `shared/dist`，继续使用原来的服务端输出路径。
- 部署保留共享包和 workspace 链接，沿用根目录安装、构建、启动流程。没有数据库、状态字段或浏览器存储迁移。
- `npm test -w @ai-runtime/shared` 验证公共状态规则；服务端原导入路径另有兼容性回归。

## 对话入口共用语义分流

`services/conversationRouting.ts` 和 `conversationIntent.ts` 提供小迪与工作台共用的意图提示、输出校验、格式修复和 CLI 调用。旧小迪导入路径保留为转发。

工作台在读取仓库、创建 worktree、加载接口文档之前，先用禁用工具的 conversation 调用理解消息。它只接收当前消息、最多 12 条各 600 字的历史及简短任务索引；闲聊直接回答，意图不明确时先提问，开发相关请求进入原有分析和执行流程。分类失败不会默认进入代码执行。

闲聊保留原任务的状态、待补充问题和审查成果；补充答案、图片及明确取消/分支操作保留原处理约束。收到新要求或暂停时，不把过期的分流结果推进到代码分析。普通聊天仍消耗一次语义判断/回答的模型调用，不包含仓库和整份接口文档；已有固定问候快捷回复继续不调用模型。
